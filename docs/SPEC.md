# Punch in 仕様

## 目的・構成
自分で設定した種類ごとに、時間をひと押しで記録する個人向けアプリ。ChatGPT Sitesを使って作成し、Vinext / React / TypeScript / Cloudflare D1で構成する。Sitesでは所有者限定で公開し、各操作は認証済みユーザーのIDでデータを分離する。複数ユーザーへ公開する場合も所有者の明示的な共有操作が必要。

## 打刻
- 初期項目は「打刻」1つ。作業ごとに名前、色、並び順、表示・非表示を設定する。
- 旧版の4つの初期項目は、すべて未編集で記録・追加作業がない場合に限り「打刻」へ置き換える。既存の設定・記録・個人編集は保持する。
- 通常の打刻は別の作業を押すと共通の記録へ並行追加し、同じ作業を押すと対象だけ終了する。並行中は対象作業だけを終了し、一時停止中の作業を押すと再開する。
- 押下時刻はサーバー時刻で補正した端末の時刻を送信し、サーバーが受信前60秒〜受信後2秒の範囲で検証する。未来には記録せず、不正・古すぎる値や旧クライアントは受信時刻にフォールバックする。既存区間と重ならない時刻を確定し、UTCのUnixミリ秒で永続化する。集計は元のミリ秒を加算し、表示でのみ分に切り捨てる。
- 画面を閉じてもDBの開始時刻は維持される。次回表示時に経過時間を再計算する。
- 押した直後は「保存中」として仮表示し、保存成功後に確定値へ置き換える。仮表示は確定データ・revisionを変更しない。失敗時は仮表示を外して再取得し、通信結果が不明な場合は同じmutationIdで再試行する。
- revisionによる楽観ロックとDBの部分UNIQUE INDEXで二重計測を防止する。全書き込みはD1のatomic batchで実行する。
- 同じmutationIdの直後の再試行は同じ結果を返す。その後に別更新があった場合は409を返し、古い操作を再適用しない。
- 別端末の変更は15秒ごとの条件付き取得、画面復帰・通信復帰時の取得で反映する。変更がなければ304で本文を返さず、非表示・保存中は定期取得を控える。
- 通常の打刻はDB読み取り・書き込みの2往復で確定し、変更した最大2記録だけ返す。全履歴の再読み込み・返送は行わない。旧クライアントと直前の同一操作の再試行は全体レスポンスに対応する。
- 履歴の絞り込み・確定時間の合計・グラフ集計は入力データが変わったときに再計算し、毎秒は計測中の経過分だけ加算する。

## 日付
- ユーザーごとに1日の開始時刻（00:00〜23:59）とIANAタイムゾーンを設定する。初期値は05:00 / Asia/Tokyo。
- 開始時刻の現地日付について、時分が日の開始より前なら暦上の前日、それ以外なら当日を記録日とする。
- 終了が区切りをまたいでも分割せず、全時間を開始側の記録日に計上する。日別合計が24時間を超える場合がある。
- 開始時の記録日・日の開始・タイムゾーンを各記録へ保存する。設定変更は過去の記録に影響しない。
- 開始時刻を手動修正すると、当該記録が保持する日の開始・タイムゾーンを使って記録日を再計算する。
- UTCで保存した時刻からタイムゾーンを使って表示し、端末のタイムゾーンに依存させない。夏時間に存在しない日時入力は拒否する。

## 作業の種類と記録
- 作業を削除しても過去の記録と集計は維持する（作業はアーカイブ）。計測中の種類は終了後に削除できる。
- 非表示は打刻画面から隠すだけ。計測中の非表示作業には終了操作を表示する。
- 名称・色の変更は同じ種類の過去の表示にも反映する。別の分類にしたい場合は新規作成する。
- 記録を手動追加・編集・削除できる。開始・終了、作業、任意メモ（最大2000文字）を編集する。
- 未来の日時、終了が開始より前の記録、既存の記録に重なる時間を拒否する。終了の空欄は計測中を表す。
- 削除は確認後に実行する。削除済みの記録はJSONバックアップから新規IDとして扱わず、元のIDのまま復元できる。

## 履歴・集計
- 履歴は記録日の範囲、作業の種類、作業名・メモ検索で絞り込む。通常は選択した日を含む週の7日分を表示する。日付の範囲を指定した場合はその範囲に限定する。
- 履歴では7日を縦に並べ、共通の時間軸と種類別の色で週のタイムラインを表示する。
- 日・週・月・年・全期間について、種類別の時間と全種類の総計を表示する。週は月曜始まり、月・年は暦どおり。
- 期間内の記録日の開始した作業を集計する。開始・終了による期間内クリッピングはしない。
- 日・週・月・年には直前の同単位の期間との比較を表示する。現在進行中の期間も前期間の全体と比較する。
- 計測中の経過時間を加える場合は「計測中を含む」と表示する。CSVにも暫定値かを含める。
- 集計グラフは日ごと、年・全期間は月ごとに積み上げ表示する。

## 通知
- 終了忘れ通知は任意。開始から設定した分数（1〜10080分、初期360分）経過すると、同一記録について端末ごとに1回通知する。
- アプリが開いている間に動作する。画面内に通知し、許可されている場合はブラウザ通知も出す。タブを閉じた後のプッシュ配信、メール、OSがタブを停止した間の配信は対象外。
- 通知許可は利用者が設定を有効にした操作に続いて求める。許可しなくても画面内通知は利用できる。通知による自動終了はしない。

## データ移行
- JSON v4で作業・記録・日別メモ・個人設定を一括出力する。ユーザーID、認証情報、メールは出力しない。
- インポート先の認証済みユーザーへ関連づける。IDは種類・記録ともに保持する。
- 同一IDは既存データを優先してスキップし、上書きしない。件数と計測中の復元を事前表示する。
- 設定の取り込みはチェックで選べる。取り込み前に形式・バージョン・参照・記録日の整合性・時間の重複を検証し、全体を一括保存する。
- ファイルは16MB、種類500件、記録20000件まで。CSVは履歴の絞り込み結果と、集計の選択期間について出力する。
- 個人設定には色、タイムゾーン、日の開始、通知設定を含める。ブラウザ自体の通知許可は移行しない。

## UI
- ページタイトルは「Punch in」のみ。
- ロゴはユーザー指定のpunch-in-icon-v2.pngを使用。余白を整えた軽量画像をヘッダー、favicon、Apple/Androidホーム画面、通知へ設定する。元画像も保持する。
- マネーフォワード クラウド勤怠Plusの提供画像を参考にする。濃色サイドバー、白い領域、大きな時計、画面幅によらず丸い枠線ボタン。
- 上部ヘッダーはPC 52px・スマホ48px、ページ見出しはPC 48px・スマホ44px。ヘッダーにタイムゾーンは表示しない。
- 不要な副見出し・説明文を置かず、余白と配置で操作を伝える。打刻にメモ入力・確認ダイアログを必須にしない。
- 計測中は塗りつぶし・停止アイコン・短い状態表示で区別する。色だけには依存しない。
- 計測中の経過時間は作業名の下に独立した段で大きく表示する。通常44px、狭い作業領域では32〜40pxとし、時・分を見やすくする。
- サイドバーの初期色とカラーリセット時の色は真っ黒（#000000）。作業の色に加えてアクセント・サイドバー色を個人設定し、背景の明るさから文字色を自動選択する。
- 画面切り替え・ボタン・ダイアログ・通知に140〜220msの短い動きを付ける。時計や経過時間はアニメーションしない。端末の「動きを減らす」設定を尊重する。
- フォームのラベル、キーボードフォーカス、モーダルのフォーカス制御、エラー表示を用意する。

## 日別ブロックメモ

- 1ユーザー・1記録日につき1つ。作業・打刻ごとの既存メモとは独立する。
- 打刻ボタンは時計の下。打刻・履歴の見出し右の「メモ」で、右から約200msで開く白い編集領域を表示する。角丸・カード枠・影は付けない。
- 表示された本文へ直接入力する。編集・プレビューのモードを分けない。履歴の日付の見出し行を押すとその日のメモを開き、スクロール中も開いた日付を固定する。狭い幅では打刻の下・履歴一覧の上にメモを並べ、両方を操作できるようにする。
- 打刻で開く日付は本人の1日の開始時刻・タイムゾーンで決める。開いたメモの日付は区切り時刻を越えても固定し、入力を別の日に移さない。
- 入力が約800ms止まると自動保存する。閉じたときは待機中の保存を開始し、画面を閉じてもブラウザ内の下書きを保持する。通信失敗は再試行できる。別画面との競合は自動上書きせず選択を求める。
- 段落・見出し・リスト・チェックリスト・折りたたみ・コード・引用・表をブロックとして扱う。六点メニューで種類を変更し、表を挿入できる。ホバーできない端末には選択中ブロックのタップ用ハンドルを表示する。本文最大100000文字、構造JSONは700000バイト・5000ブロック・子ブロック深さ16まで。
- メモ本文は通常の打刻・state取得に含めない。専用APIと版管理、入力状態の分離、遅延読み込みで打刻の応答性を保つ。
- JSON v4にMarkdown・ブロック構造・移行前の原文を含め、v1/v2/v3の取り込みにも対応する。メモ単体はMarkdownでも書き出せる。CSVは打刻と集計用。

## 可変幅のレイアウト

- 1200px以下ではサイドバーをメニューボタンに収める。メニューは背景クリック・閉じるボタン・Escapeで閉じる。メニュー内のTab移動を保ち、閉じると呼び出しボタンへフォーカスを戻す。
- 761px以上ではメモと作業領域を左右に並べ、メモを開いても打刻ボタンを覆わない。760px以下ではメモを打刻の下、履歴一覧の上に置く。入力・保存・カーソル状態は幅の変更で作り直さない。
- 打刻ボタンの並びは作業領域の実際の幅に合わせる。狭い領域でも丸いまま最大2列、1種類だけなら中央に1個。長い名前を折り返し、追加ボタンも領域内に置く。
- 保存済みのチェックマークは表示しない。自動保存は続け、読み込み中・保存中・保存エラー・競合のみ状態を表示する。
- 横に長い履歴表・タイムラインは各領域でスクロールし、画面全体の横スクロールを起こさない。

参考: [CSSコンテナクエリー](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)、[aria-expanded](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-expanded)。

## 打刻ボタンの整列

- 広い作業領域は最大3列とし、各段の個数の差を1以内に揃える。4個は2+2、5個は3+2、7個は3+2+2、10個は3+3+2+2。最後の段だけ1個を残さず、各段を中央揃えにする。
- 作業領域が520px以下なら最大2列。奇数の最後の1個も中央に置く。ボタンは幅によらず正円を保ち、1種類だけなら中央に1個置く。
- 非表示・アーカイブを除いたボタン数で決め、登録順を保つ。「＋」は作業の段とは別に、その下の中央に置く。種類が増えてもボタンを縮小せず、縦スクロールで扱う。
- 配置は表示件数が変わったときだけ計算し、幅の切り替えはCSSで行う。打刻API・保存処理には変更を加えない。

## 打刻ごとのメモと集計の確認

- 「今日の記録」「履歴」のメモセルは、ボタンではなく常に入力できるtextarea。クリックまたはTabで入力し、約800msの停止後・フォーカス移動時に自動保存する。改行可能、上限2000文字。
- 保存中も打刻可能。ブラウザ下書きをユーザー・記録ID別に保持し、通信エラーでは再試行、競合では最新版と入力内容のどちらを残すか選べる。正常保存のチェックアイコンは出さない。
- スマホや狭い作業領域では、各記録の時刻の下にメモ欄を横幅いっぱいで表示する。横スクロールでメモ欄を探す必要をなくす。
- 集計のグラフ・表・内訳は同じ期間・カテゴリ絞り込みを使う。表は日・週・月なら日別、年・全期間なら月別。カテゴリごとの時間と行合計・期間合計を「N時間MM分」で表示し、24時間超も切り詰めない。
- グラフの棒をホバーまたはキーボードでフォーカスすると、通信せず即座に合計・カテゴリ別時間・各打刻の開始終了日時とメモを表示する。内訳の上へ移動しても閉じず、長い本文をスクロールで読める。Escape・閉じる操作に対応する。
- PCで棒を押すとその日／月の履歴へ移動し、カテゴリの絞り込みも引き継ぐ。スマホはタップで内訳を開き、その中の「履歴を見る」で移動する。
- Punch inのロゴは打刻ホームへ戻り、ページ先頭を表示する。キー操作にも対応する。
- 入力欄のフォーカスや内訳の表示には120ms程度の短い変化だけを付ける。時計や経過時間を動かさず、prefers-reduced-motionを尊重する。

## ボタン・スクロール・削除操作

- 「記録を追加」などの主操作は白地・アクセント色の細いアウトラインとし、個人の配色設定に従う。打刻ボタンは丸型を維持する。
- 日別メモ、記録メモ、編集ダイアログ、メモ内のコード・表、集計の内訳はスクロールバーを表示しない。スクロール機能は維持し、メモ領域はキーボードでも操作できる。
- 計測開始・終了時は経過時間の領域を220msで開閉し、下の打刻ボタンも連動して移動する。毎秒の数字更新では動かさず、動きを減らす設定では即時表示する。
- 今日の記録と履歴の行末に編集・削除を並べる。削除は対象の日付・開始時刻・作業名を確認し、未保存のメモの保存を待って実行する。失敗時は確認画面と下書きを残す。成功後は当該記録の下書き・保存予約を除去する。

## 履歴の週表示

- 7日分のタイムラインを上部に固定し、一覧の閲覧位置に合わせて該当日の行を強調する。並行する区間は上下のレーンに分け、狭い画面でも7日を維持する。
- 月曜から日曜の7日を表示し、記録がない日はコンパクトに表示する。
- 週は前週・次週・今週で切り替える。1日の記録は40件ずつ描画し、必要に応じて追加表示する。
- 日付の見出し行全体を押すと当日のメモを開く。記録のメモ欄の直接入力、行末の編集・削除とは分ける。スクロールや日付指定だけでは開いているメモを変更しない。
- 小さい画面では日付を押すとメモまでスクロールし、閉じると該当日の一覧へ戻す。
- 数字ショートカットはNotionの割り当てに合わせる。0=本文、1〜3=見出し、4=チェック、5=箇条書き、6=番号、7=折りたたみ、8=コード。Windows/LinuxはCtrl+Shift、MacはCmd+Optionを併用し、IME変換中は発火させない。

- リストのTab/Shift+Tabは階層を1段ずつ変更し、階層も構造JSONに保存する。コードではTabで空白を挿入し、表では次のセルへ移動する。通常のブラウザのキー操作と混同しないよう、エディター内の文脈に従う。

## 並行作業・一時停止・配分

- 履歴では共通の開始・終了を持つ1行にまとめ、作業ごとの計上時間と直接入力できるメモを内側に並べる。
- 作業は途中追加・終了・再打刻できる。終了後の再打刻は同じ親記録内に別の記録ID・開始・終了・メモを持つ作業として追加する。一時停止からの再開は同じ記録とメモを継続する。
- 作業ごとに一時停止・再開できる。全作業停止中も記録は未終了のまま保持し、実時間と自動配分は増えない。
- 初期配分は、各区間で計測中の作業へ均等配分する。10:00開始のAに10:20からBが加わり11:00終了なら、A40分・B20分。
- 終了後は均等・比率・時間を切り替えられる。個別時間は合計を実時間へ合わせる制約を設けない。実時間1時間に対しA1時間・B45分も指定可能。
- 実時間は有効区間の合計、計上時間は作業別の配分合計。配分編集は共通の開始・終了と実際のタイムラインを変えない。
- 日別の所属は共通記録の開始時点で決める。既存の単独記録は元の作業へ100%計上する。
- 日付行を押すと日付・日合計・タイムライン・メモを同期する。以降のスクロールでは日付・タイムラインが追従し、メモはクリックした日に固定する。

## 日別メモのテンプレート

- 空から名前付きテンプレートを作成し、編集・複製・削除できる。既存の日別メモから作成する機能は設けない。
- 最初に作ったテンプレートを自動挿入の初期選択にし、別のものや「なし」に変更できる。
- 日のメモを初めて開く際、選択したテンプレートを自動挿入する。既存・削除済み本文・ブラウザの未保存下書きには再挿入しない。
- その日に使うテンプレートを変更できる。未編集なら置き換え、入力済みなら末尾への追加か置き換えを選ぶ。
- 各日のメモとテンプレート本体は独立し、変更を遡って反映しない。挿入・複製の際にブロックIDを更新し、表や入れ子を保つ。
- テンプレートは日別メモ専用。作業ごとの短いメモには適用しない。
- 先頭リストの最初の表示行でArrowUpを押すと、文字の有無によらず上に本文を追加して移動できる。通常のTab・Shift+Tab・Undo・IMEの操作を保つ。

## 週単位の履歴と作業別操作

- 履歴は月曜〜日曜を1ページにし、記録がない日も含め7日分を時刻順に並べる。日ごとの記録は新しい順。前週・次週・今週で移動し、週全体のタイムラインを上部に表示し、選択日を強調する。週のナビゲーションだけを固定する。
- 日付入力でその日を含む週へ移動する。検索・種類フィルターはその週の記録へ適用し、期間指定中の前後移動は指定期間内の週に限る。「今週」で期間指定を解除する。
- 日付行でタイムラインとメモを同期し、その後のスクロール・週移動ではメモを選択日に固定する。記録がない日はコンパクトに表示する。
- 並行記録は全体か作業1つを選んで削除する。残りのメモは保ち、自動配分は残った参加者へ再計算、手動の指定時間は維持する。削除した作業だけの区間は実時間から取り除く。
- 打刻ごとの開始・終了と、展開できる各計測区間を表示する。過去の記録で個別終了が保存されていなければ、最後に計測した区間の終端を表示する。
- 経過時間は計測中の種類の色を斜めに均等分割する。一時停止中の種類の色を除き、全員停止中は落ち着いた単色にする。
- 集計の主表示・前期間比較・グラフ・内訳・割合・表・CSVは計上時間へ統一する。集計には実時間の合計を併記しない。打刻と履歴の合計は重複なしの実時間を維持する。
- ボタンの並び替えは「ボタンを編集」から開く設定一覧の六点ハンドルで行い、ドロップ時に1回保存する。キーボードではSpace/Enterで移動開始、上下キーで移動、Enterで確定、Escapeで中止する。

## 一括停止・保存表示・日付の強調

- 並行中の作業を「まとめて一時停止」できる。停止した対象を記録し、「まとめて再開」ではその対象のうち一時停止中の作業だけ再開する。先に個別停止していた作業を勝手に再開しない。
- 一括停止の対象は再読み込み・JSONバックアップでも保持する。個別に再開・終了・削除した作業は対象から除き、個別に再停止しても自動で対象に戻さない。全体終了でも対象を消す。
- 一括操作はアイコン付きアウトラインボタンとし、狭い画面では折り返す。再開は薄いアクセント、終了は控えめな別色の枠線で区別する。
- 日別メモのヘッダーに保存済みチェック・保存中・失敗・競合の状態を表示する。チェックは操作ボタンではなく、サーバーで保存を確認した状態を示す。自動保存と既存の再試行を継続する。
- 履歴を開くたびに今日を含む週のタイムラインから表示し、今日を強調する。同じ週でも再実行する。集計から特定日へ移動した場合はその日を優先し、スクロールや週移動で開いているメモを変更しない。「今週」の名称は維持する。
- 履歴の日付行を薄いグレーの帯で区切り、タイムラインに表示中の日には薄いアクセントを付ける。メモを開いている日は左の細い線で区別する。
- 集計表では今日の行、月別表では当月の行を薄いアクセントで表示する。今日の判定には設定済みのタイムゾーンと一日の開始時刻を使う。


## 終了時刻・再打刻・週タイムライン（2026-11-04）

- 一時停止中に終了した場合は、その記録が最後に計測した区間の終端を終了時刻にする。一括終了でも作業ごとに適用し、親記録の終了は各記録のうち最も遅い終了時刻とする。操作日時はupdatedAtへ保持する。
- 同じカテゴリを終了後に再打刻した場合は別の記録を追加する。新しいメモは空で開始し、前の記録の時刻・メモは保持する。履歴内の個別削除と配分編集も記録IDで扱い、集計はカテゴリごとに合算する。
- タイムラインは設定された日の区切り・タイムゾーンで7日分を表示する。日をまたぐ実区間は各日の表示範囲で切り分ける。タイムラインの小計は表示範囲の実時間、履歴の日合計・集計は従来どおり開始日の所属に従う。
- タイムラインの日付は履歴への移動、履歴の日付行はメモを開く操作とする。スクロールとタイムラインの日付選択はメモの日付を変更しない。
- 並行区間は3レーンまで、各日160区間まで描画する。省略分は件数ボタンから履歴へ移動して確認する。履歴グループ内は直近50記録から追加表示し、ホバー内訳も30記録ずつ表示する。


## 記録の表示・日時編集（2026-11-04）

- UIでは作業の分類を「作業」、重複なしの有効区間の合計を「記録時間」、配分後の時間を「作業時間」、日単位のMarkdownを「日別メモ」と呼ぶ。計算方法は変更しない。
- 今日の記録と履歴は作業ごとの薄い背景色と左の色線で区別し、主要な時間を大きく表示する。共通時刻と一致する個別時刻・重複する合計を省略する。各作業のメモは欄に直接入力し、通常は2行、フォーカス時に拡張する。
- 計測区間の開閉は履歴だけに表示し、打刻画面には表示しない。履歴の上部追加ボタンをなくし、空の日を含む日付行の＋から追加する。
- 新規追加は選んだ記録日と現在の時刻を初期値とする。日の区切りより前の時刻なら翌暦日に合わせる。開始・終了の初期値は同じ時刻で、保存時の重複・未来時刻などの制約を維持する。既存の編集は保存済み日時から始める。
- 日付（年・月・日）と時刻（時・分）を中央選択式のホイールで設定する。矢印キー・PageUp/Down・Home/Endと直接入力にも対応する。月・年の変更で存在しない日は末日に合わせ、未変更の保存は元のミリ秒も保つ。
- 並行記録の編集は作業時間・日時を切り替え、日時では対象記録を選ぶ。一時停止の内部区間、他の作業の日時・メモ・手動配分を保持する。同じ作業の再打刻や別の親記録との重複を拒否する。
- タイムライン自体は縦スクロールに固定せず、7日分を同じ横スクロール領域に表示する。日付・小計列は左右に残し、拡大・縮小・全体表示に対応する。初期表示はPCで8時間、狭い画面で4時間。手動で変えた表示範囲は拡大・画面幅変更時も中心の時刻を維持する。
- 集計などから特定日へ移動した場合は該当する日付行へ移動する。スクロール中も開いている日別メモの日付は固定する。


## 分単位の表示と時刻の配置（2026-11-04）

- 時計・経過時間・履歴・集計・ホバー・計測区間・配分編集・日時入力は秒を表示しない。日時ホイールは時・分の2列とし、直接入力も1分単位にする。
- DB、API、復元用JSONは従来のミリ秒精度を維持する。正確な値を合算してから表示を分へ切り捨てるため、表示された内訳の和と表示合計に分未満の差が出る場合がある。
- 保存済みの日時・手動配分は、表示上の分を変更しなければ元の秒・ミリ秒を保持する。分を変更した日時はその分の00秒、手動配分は整数分として保存する。
- CSVの時間列は整数分、日時はUTCの分単位表記（例：2026-11-04T03:34Z）とする。完全な復元にはJSONを使用する。
- 今日の記録と履歴の各作業は、作業名を左、作業時間と開始・終了を右にそろえる。開始と終了は小さな線と点でつなぎ、共通時刻と一致する場合も各作業で確認できるようにする。
- 日合計は24px、作業ごとの時間は18px（狭い領域は17px）、開始・終了時刻は14px（同13px）を基本とする。作業時間は「1時間30分」「0時間45分」「2時間00分」と表示し、分未満は「0時間00分」とする。
- 週タイムラインの時間目盛りは専用32pxの行へ配置する。日付列・時間軸・小計列を各日の列とそろえ、最初の日のバーや日付と重ねない。


## 時間と分の表記統一（2026-11-04）

- 経過時間・日合計・各作業・配分編集・集計表・ホバー・前期間比較・週タイムラインの小計は「N時間MM分」に統一する。共通部品DurationValueを使い、「時間」「分」は数字より小さく表示する。
- 数字のサイズは親の強弱を引き継ぎ、日合計は各作業より大きくする。単位は相対サイズと最小10pxを使う。時計・開始終了・目盛りの時刻はHH:mmを維持する。CSVの「時間」列も同じ文字表記とし、数値の分数列は維持する。
- 表示の変更だけでDB・API・復元用JSON・分未満の合算方法は変更しない。


## HH:mmの所要時間と時計アイコン（2026-11-04）

- 時間の主表示はDurationValueを共用し「01:30」の形式へ統一する。時計・開始終了もHH:mmだが、記録一覧・計測区間・配分編集・集計ホバーの開始終了には小さな時計アイコンを添えて見分けられるようにする。
- 経過時間・日合計・各作業の文字サイズの強弱は維持する。タイムラインの時刻目盛りにはアイコンを追加しない。
- CSVの文字列の時間列はHH:mm、数値の分数列とDB/API/JSONの精度は維持する。読み上げラベル・通知などの文章には時間と分の表記を使う。
