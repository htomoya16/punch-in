# Punch in 仕様

## 目的・構成
研究、個人開発、就活など、個人の活動時間をひと押しで記録する。Sites / Vinext / React / TypeScript / Cloudflare D1。Sitesでは所有者限定で公開し、各操作は認証済みユーザーのIDでデータを分離する。複数ユーザーへ公開する場合も所有者の明示的な共有操作が必要。

## 打刻
- 初期項目は「打刻」1つ。作業ごとに名前、色、並び順、表示・非表示を設定する。
- 旧版の4つの初期項目は、すべて未編集で記録・追加作業がない場合に限り「打刻」へ置き換える。既存の設定・記録・個人編集は保持する。
- 同時に計測できるのは1種類。別の作業を押すと、同じ時刻で現在の計測を終了して次を開始する。同じ作業を押すと終了する。
- 押下時刻はサーバー時刻で補正した端末の時刻を送信し、サーバーが受信前60秒〜受信後2秒の範囲で検証する。未来には記録せず、不正・古すぎる値や旧クライアントは受信時刻にフォールバックする。既存区間と重ならない時刻を確定し、UTCのUnixミリ秒で永続化する。集計は元のミリ秒を加算し、表示でのみ秒・分に切り捨てる。
- 画面を閉じてもDBの開始時刻は維持される。次回表示時に経過時間を再計算する。
- 押した直後は「保存中」として仮表示し、保存成功後に確定値へ置き換える。仮表示は確定データ・revisionを変更しない。失敗時は仮表示を外して再取得し、通信結果が不明な場合は同じmutationIdで再試行する。
- revisionによる楽観ロックとDBの部分UNIQUE INDEXで二重計測を防止する。全書き込みはD1のatomic batchで実行する。
- 同じmutationIdの直後の再試行は同じ結果を返す。その後に別更新があった場合は409を返し、古い操作を再適用しない。
- 別端末の変更は15秒ごとの条件付き取得、画面復帰・通信復帰時の取得で反映する。変更がなければ304で本文を返さず、非表示・保存中は定期取得を控える。
- 通常の打刻はDB読み取り・書き込みの2往復で確定し、変更した最大2記録だけ返す。全履歴の再読み込み・返送は行わない。旧クライアントと直前の同一操作の再試行は全体レスポンスに対応する。
- 履歴の絞り込み・確定時間の合計・グラフ集計は入力データが変わったときに再計算し、毎秒は計測中の経過分だけ加算する。

## 日付
- ユーザーごとに1日の開始時刻（00:00〜23:59）とIANAタイムゾーンを設定する。初期値は05:00 / Asia/Tokyo。
- 開始時刻の現地日付について、時分が日の開始より前なら暦上の前日、それ以外なら当日を記録日とする。
- 終了が区切りをまたいでも分割せず、全時間を開始側の記録日に計上する。日別合計が24時間を超える場合がある。
- 開始時の記録日・日の開始・タイムゾーンを各記録へ保存する。設定変更は過去の記録に影響しない。
- 開始時刻を手動修正すると、当該記録が保持する日の開始・タイムゾーンを使って記録日を再計算する。
- UTCで保存した時刻からタイムゾーンを使って表示し、端末のタイムゾーンに依存させない。夏時間に存在しない日時入力は拒否する。

## 作業の種類と記録
- 作業を削除しても過去の記録と集計は維持する（作業はアーカイブ）。計測中の種類は終了後に削除できる。
- 非表示は打刻画面から隠すだけ。計測中の非表示作業には終了操作を表示する。
- 名称・色の変更は同じ種類の過去の表示にも反映する。別の分類にしたい場合は新規作成する。
- 記録を手動追加・編集・削除できる。開始・終了、作業、任意メモ（最大2000文字）を編集する。
- 未来の日時、終了が開始より前の記録、既存の記録に重なる時間を拒否する。終了の空欄は計測中を表す。
- 削除は確認後に実行する。削除済みの記録はJSONバックアップから新規IDとして扱わず、元のIDのまま復元できる。

## 履歴・集計
- 履歴は記録日の範囲、作業の種類、作業名・メモ検索で絞り込む。20件単位でページを分ける。
- 1日表示では種類別の色を使ったタイムラインを表示する。長時間の記録は表示範囲を拡張する。
- 日・週・月・年・全期間について、種類別の時間と全種類の総計を表示する。週は月曜始まり、月・年は暦どおり。
- 期間内の記録日の開始した作業を集計する。開始・終了による期間内クリッピングはしない。
- 日・週・月・年には直前の同単位の期間との比較を表示する。現在進行中の期間も前期間の全体と比較する。
- 計測中の経過時間を加える場合は「計測中を含む」と表示する。CSVにも暫定値かを含める。
- 集計グラフは日ごと、年・全期間は月ごとに積み上げ表示する。

## 通知
- 終了忘れ通知は任意。開始から設定した分数（1〜10080分、初期360分）経過すると、同一記録について端末ごとに1回通知する。
- アプリが開いている間に動作する。画面内に通知し、許可されている場合はブラウザ通知も出す。タブを閉じた後のプッシュ配信、メール、OSがタブを停止した間の配信は対象外。
- 通知許可は利用者が設定を有効にした操作に続いて求める。許可しなくても画面内通知は利用できる。通知による自動終了はしない。

## データ移行
- JSON v1で作業・記録・個人設定を一括出力する。ユーザーID、認証情報、メールは出力しない。
- インポート先の認証済みユーザーへ関連づける。IDは種類・記録ともに保持する。
- 同一IDは既存データを優先してスキップし、上書きしない。件数と計測中の復元を事前表示する。
- 設定の取り込みはチェックで選べる。取り込み前に形式・バージョン・参照・記録日の整合性・時間の重複を検証し、全体を一括保存する。
- ファイルは16MB、種類500件、記録20000件まで。CSVは履歴の絞り込み結果と、集計の選択期間について出力する。
- 個人設定には色、タイムゾーン、日の開始、通知設定を含める。ブラウザ自体の通知許可は移行しない。

## UI
- ページタイトルは「Punch in」のみ。
- ロゴはユーザー指定のpunch-in-icon-v2.pngを使用。余白を整えた軽量画像をヘッダー、favicon、Apple/Androidホーム画面、通知へ設定する。元画像も保持する。
- マネーフォワード クラウド勤怠Plusの提供画像を参考にする。濃色サイドバー、白い領域、大きな時計、PCの丸い枠線ボタン、スマホの縦並び長方形ボタン。
- 上部ヘッダーはPC 52px・スマホ48px、ページ見出しはPC 48px・スマホ44px。ヘッダーにタイムゾーンは表示しない。
- 不要な副見出し・説明文を置かず、余白と配置で操作を伝える。打刻にメモ入力・確認ダイアログを必須にしない。
- 計測中は塗りつぶし・停止アイコン・短い状態表示で区別する。色だけには依存しない。
- サイドバーの初期色とカラーリセット時の色は真っ黒（#000000）。作業の色に加えてアクセント・サイドバー色を個人設定し、背景の明るさから文字色を自動選択する。
- 画面切り替え・ボタン・ダイアログ・通知に140〜220msの短い動きを付ける。時計や経過時間はアニメーションしない。端末の「動きを減らす」設定を尊重する。
- フォームのラベル、キーボードフォーカス、モーダルのフォーカス制御、エラー表示を用意する。
